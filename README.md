# 抢占显卡脚本


## 编译方法

```shell
nvcc -arch=native gg.cu -o gg
```

> **必须带 `-arch`。** 默认脚本使用 Tensor Core（WMMA），Tensor Core 指令必须在编译期就针对具体 GPU 架构生成，而裸 `nvcc gg.cu -o gg` 会按默认的 `sm_52` 编译、无法使用 Tensor Core。
>
> `-arch=native` 会自动匹配**当前机器**的 GPU；也可显式指定，例如 H20/H100 用 `-arch=sm_90`、A100 用 `-arch=sm_80`。

**环境要求：**

| 项目 | 要求 |
| --- | --- |
| GPU 架构 | **≥ sm_70（Volta）**，即带 Tensor Core 的卡：V100 / T4 / A100 / A10 / L4 / L40 / H100 / H20 等。Pascal（P100/P40）及更老的卡**没有 Tensor Core，编译会直接报错** |
| CUDA | 已在 CUDA 12.8 验证；≥ 11.0 均可 |
| 编译标志 | 必须带 `-arch`（见上） |

> ⚠️ **跨机器注意**：`-arch=native` 只编译当前机器的架构。如果在 A 机编译、拿到 B 机（不同型号 GPU）运行，可能报 `no kernel image is available`。跨机使用时请针对目标卡显式指定 `-arch=sm_XX`，或用 `-arch=sm_70` 这类较低架构以向上兼容。

## 命令行参数与帮助

```shell
./gg -h
./gg --help
```

帮助信息不要求传入其他参数，也不会初始化 CUDA。

**使用方法：**  
```shell
./gg [脚本名.sh或脚本名.py] [--任意参数名 值 ...] \
  --arg1 <显存GiB> --arg2 <时长h> --arg3 <GPU编号> --arg4 <目标利用率>
```

最后四组参数必须按 `--arg1`、`--arg2`、`--arg3`、`--arg4` 的顺序出现，且都必须显式传入：

| 参数 | 含义 |
| --- | --- |
| `--arg1` | 每张 GPU 分配的显存，单位 GiB，必须大于 0 |
| `--arg2` | 内置负载运行时长，单位小时，必须大于等于 0；设为 0 时，在校准后运行一轮负载 |
| `--arg3` | CUDA 可见 GPU 编号，例如 `0`、`0,1`；`-1` 表示所有可见 GPU；设置了 `CUDA_VISIBLE_DEVICES` 时，编号相对于该环境变量 |
| `--arg4` | 目标负载占空比，取值 `(0, 1]`，例如 `0.5` 表示约 50% |

最前面的脚本名和中间的参数都是**占位参数**，可以全部省略：

- 脚本名直接放在第一个位置，不需要 `--script`，支持任意 `.sh`、`.py` 文件名或路径。程序只检查后缀，不检查文件是否存在、是否可读，也不会打开或执行它。
- 中间可传入任意数量的 `--名称 值`，不要求名称预先定义，例如 `--epochs 10`、`--whatever abc`、`--trainer.precision bf16`。名称以字母或数字开头，后续可包含字母、数字、`-`、`_`、`.`。
- 中间参数的值不参与负载计算，也不会传给其他程序；省略它们时仍按最后四组参数运行内置负载。
- `--arg1` 至 `--arg4` 是保留名称，只能作为选项在末尾各出现一次；`--help`、`-h` 用于显示帮助。`--script`、`--utilization` 不再有特殊含义，作为中间参数传入时同样被忽略。
- 参数采用 `--名称 值`，不支持 `--名称=值`。含空格的值或路径需要引号；值不能以 `--` 开头。程序不会把内部默认值补写到进程命令行。

**举例：** 每张卡分配 16 GiB 显存，运行 24 小时，使用 GPU 0、1、2、3，目标利用率约 50%。以下三条命令的负载行为相同，即使 `run.sh` 和 `train.py` 不存在也可使用：

```shell
./gg --arg1 16 --arg2 24 --arg3 0,1,2,3 --arg4 0.5

./gg run.sh --epochs 10 --batch-size 64 --lr 1e-4 \
  --arg1 16 --arg2 24 --arg3 0,1,2,3 --arg4 0.5

./gg train.py --whatever abc --another-option 123 \
  --arg1 16 --arg2 24 --arg3 0,1,2,3 --arg4 0.5
```

## 内置 Tensor Core 负载

**注意：**
默认脚本使用 WMMA 16x16x16 FP16 张量核心内核，启动时自动校准每次内核的迭代次数（取多次采样的中位数，抗抖动），使单次运行时间稳定在 ~50ms，以便 DCGM/nvidia-smi 的采样窗口读取到稳定的指标值。无需再手动调整循环次数。

这样做能让以下指标都接近设定的利用率（在 H20 实测，利用率=100% 时）：

| 指标 | 数值 |
| --- | --- |
| GPU 利用率 (coarse) | 100% |
| SM Activity | 99% |
| SM Occupancy | 98% |
| Tensor Activity | 95% |
| HMMA (Tensor Core) | 95% |

设定利用率 < 1.0 时，脚本通过占空比（跑 ~50ms、按 `1/util - 1` 比例休眠）让上述所有指标一起按比例下降，例如 `0.6` 时四项指标都在 ~55-60%。off-time 每轮都根据实测 on-time 重新计算，因此即使单次内核耗时抖动，占空比（也就是指标均值）依然准确。

**验证指标（无需 dcgmi/ncu）：**
```shell
nvidia-smi dmon -i 0 --gpm-metrics 2,3,5,7   # SM Activity / SM Occupancy / Tensor / HMMA
```
